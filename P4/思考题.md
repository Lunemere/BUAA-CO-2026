# 第一题

**addr 来自 ALU 的运算结果**，一般是 `GPR[base] + sign_extend(offset)`。它和 **PC 一样都是 32 位字节地址**，而 **DM 的每个存储单元是一个 32 位字**，所以必须把这个字节地址折算成"第几个字"，这就是下标是 `[11:2]` 的原因：**低 2 位是对齐信息，不是单元编号，被丢掉；下标从第 2 位开始向上取，正好得到"字地址"；10 位下标对应 2¹⁰ = 1024 个字 = 4KB。**

# 第二题

- **方式 A：译码后"按信号合成"（一热译码 + 或阵列）**
  先为每条指令生成一个一热的译码位，再把每个控制信号写成"哪些指令会把它拉高"的或表达式；
- **方式 B：按指令"整行赋值"（`case` / 优先级选择）**
  把真值表按行搬进代码，每条指令给出自己那一整套控制值。

## 方式 A：一热译码 + 或阵列

```verilog
module Controller_A(
    input  [5:0] OpCode,
    input  [5:0] Funct,
    output [2:0] NPC_Sel,
    output       RFWr,
    output [3:0] type,
    output       EXTOp,
    output       ALUSrc,
    output       RegDst,
    output       Mem2Reg,
    output       MemWr,
    output       Addr2Reg
    );

    // ---- 译码层：每条指令一热 ----
    wire ori  = (OpCode == 6'h0d);
    wire beq  = (OpCode == 6'h04);
    wire lui  = (OpCode == 6'h0f);
    wire sw   = (OpCode == 6'h2b);
    wire lw   = (OpCode == 6'h23);
    wire j    = (OpCode == 6'h02);
    wire jal  = (OpCode == 6'h03);
    wire sub  = (OpCode == 6'h00) && (Funct == 6'h22);
    wire add  = (OpCode == 6'h00) && (Funct == 6'h20);
    wire andi = (OpCode == 6'h00) && (Funct == 6'h24);   // 避开关键字 and
    wire jr   = (OpCode == 6'h00) && (Funct == 6'h08);

    // ---- 或阵列：一个控制信号一列 ----
    assign NPC_Sel  = ({3{jr}}      & 3'd3) |
                      ({3{j | jal}} & 3'd2) |
                      ({3{beq}}     & 3'd1);
    assign RFWr     = ori | lui | lw | sub | add | andi | jal;
    assign EXTOp    = sw | lw;
    assign ALUSrc   = ori | lui | sw | lw;
    assign RegDst   = jal | andi | sub | add;
    assign MemWr    = sw;
    assign Mem2Reg  = lw;
    assign Addr2Reg = jal;
    assign type     = ({4{ori }} & 4'd1 ) | ({4{beq }} & 4'd2 ) |
                      ({4{lui }} & 4'd3 ) | ({4{sw  }} & 4'd4 ) |
                      ({4{lw  }} & 4'd5 ) | ({4{sub }} & 4'd6 ) |
                      ({4{add }} & 4'd7 ) | ({4{andi}} & 4'd10) |
                      ({4{j   }} & 4'd9 ) | ({4{jal }} & 4'd11) |
                      ({4{jr  }} & 4'd12);
endmodule
```

## 方式 B：按行赋值（`case`）

```verilog
module Controller_B(
    input  [5:0] OpCode,
    input  [5:0] Funct,
    output reg [2:0] NPC_Sel,
    output reg       RFWr,
    output reg [3:0] type,
    output reg       EXTOp,
    output reg       ALUSrc,
    output reg       RegDst,
    output reg       Mem2Reg,
    output reg       MemWr,
    output reg       Addr2Reg
    );

    always @(*) begin
        // 默认值：未定义指令按 nop 处理
        NPC_Sel = 3'd0; RFWr = 1'b0; type = 4'd0;
        EXTOp   = 1'b0; ALUSrc = 1'b0; RegDst = 1'b0;
        Mem2Reg = 1'b0; MemWr  = 1'b0; Addr2Reg = 1'b0;

        case (OpCode)
            6'h00: case (Funct)
                       6'h20: begin RFWr=1; RegDst=1; type=4'd7;  end   // add
                       6'h22: begin RFWr=1; RegDst=1; type=4'd6;  end   // sub
                       6'h24: begin RFWr=1; RegDst=1; type=4'd10; end   // and
                       6'h08: begin NPC_Sel=3'd3;                 end   // jr
                       default: ;                                       // nop
                   endcase
            6'h0d: begin RFWr=1; ALUSrc=1; type=4'd1; end                    // ori
            6'h0f: begin RFWr=1; ALUSrc=1; type=4'd3; end                    // lui
            6'h23: begin RFWr=1; ALUSrc=1; Mem2Reg=1; EXTOp=1; type=4'd5; end // lw
            6'h2b: begin ALUSrc=1; MemWr=1; EXTOp=1; type=4'd4; end          // sw
            6'h04: begin NPC_Sel=3'd1; type=4'd2;  end                       // beq
            6'h02: begin NPC_Sel=3'd2; type=4'd9;  end                       // j
            6'h03: begin RFWr=1; Addr2Reg=1; NPC_Sel=3'd2; type=4'd11; end   // jal
            default: ;
        endcase
    end
endmodule
```

## 优劣分析

按指令赋值的可读性很好，按信号赋值的可读性不好，为了要读懂一条指令，要翻遍所有的信号表达式。按指令赋值的增删指令都是很方便的，直接改case，信号的要到处改。

按信号合成的，便于手工优化和时序分析，扩展性差可读性弱。按指令合成的，可读性、可维护性、可扩展性好。

## 第三题

* **异步复位**:`reset` 不用等时钟,它一有效,寄存器马上清零,写法是 `always @(posedge clk or posedge reset)`。优先级上 `reset` 比 `clk` 高:两次时钟沿之间只要 `reset` 来了,立刻生效;就算 `reset` 和时钟沿同时到,也是复位那条分支说了算。
* **同步复位**:`reset` 在这里就是个普通输入信号,只在时钟沿到来的那一刻被看一眼,写法是 `always @(posedge clk)`。优先级上反过来,`clk` 说了算:`reset` 拉起来了但时钟沿还没到,寄存器纹丝不动;一直等到下一个时钟沿,发现此刻 `reset` 有效,才真正复位。

## 第四题

`add` 和 `addu`、`addi` 和 `addiu`,只要不考虑溢出,效果完全一样。原因可以这样理解:

1. **运算本身是同一个。**硬件里根本没有"有符号加法"和"无符号加法"两套电路,都是把两个 32 位数按二进制加起来,再截成 32 位。补码的好处就在这儿,加法器不用管你把这些位当成有符号数还是无符号数。
2. **真正的区别只在异常上。**`add`/`addi` 在结果装不进 32 位补码(也就是有符号溢出)时,会触发 Integer Overflow 异常;`addu`/`addiu` 不管算出什么,都不会报这个异常。
3. **所以不考虑溢出,差别就没了。**异常是唯一的分叉口,既然题目说了不考虑溢出,就永远走不到那个分叉,剩下的就是一模一样的加法。换个角度看,两者的差别恰恰就是溢出时发生什么:`add` 会报异常,交给异常处理程序接管;`addu` 则默默把回绕后的结果写进寄存器,继续往下执行。
