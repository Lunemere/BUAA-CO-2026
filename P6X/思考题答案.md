# 思考题答案

## 必做题

### 1、我们使用提前分支判断的方法尽早产生结果来减少因不确定而带来的开销，但实际上这种方法并非总能提高效率，请从流水线冒险的角度思考其原因并给出一个指令序列的例子。

提前分支判断将条件比较从 E 级提到了 D 级。虽然在延迟槽存在时消除了分支预测失败的控制开销，但也将比较操作数的使用时刻（$T_{use}$）从 1 提前到了 0。这收窄了前序指令产生结果与转发的时间窗口，如果前序指令结果尚未就绪，就会引发额外的数据冒险阻塞。

**指令序列示例**：
```mips
add $1, $2, $3      # E 级算完，M 级才稳定就绪 (E 级时 Tnew = 1)
beq $1, $0, label   # D 级就需要使用 $1 比较 (D 级时 Tuse = 0)
nop
```

- **分支在 D 级判断**：`beq` 在 D 级时 `add` 在 E 级，$T_{use}(0) < T_{new}(1)$，必须在 D 级**阻塞 1 拍**。
- **分支在 E 级判断**：当 `beq` 进入 E 级时，$T_{use} = 1$，此时 `add` 已经到达 M 级（$T_{new} = 0$），可以通过 `M -> E` 转发直接把结果喂给比较器，**无需任何阻塞（0 拍）**。

因此，若程序中频繁出现计算后紧跟分支的情况，提前判断增加的数据冒险开销可能会抵消甚至超过消除控制冒险带来的收益。

### 2、因为延迟槽的存在，对于 jal 等需要将指令地址写入寄存器的指令，要写回 PC + 8，请思考为什么这样设计？

MIPS 规定分支跳转指令后紧跟的延迟槽指令（地址为 `PC + 4`）无论跳转与否都必须执行。

`jal` 用于子程序调用，需要将子程序返回后的执行地址存入 `$31`（`$ra`）：
1. 位于 `PC + 4` 的延迟槽指令紧随 `jal` 取出，在跳转前已经正常执行完毕；
2. 如果写入 `PC + 4`，子程序返回（`jr $ra`）时会再次跳回延迟槽，导致延迟槽指令被**重复执行两次**；
3. 写入 `PC + 8`，子程序返回后恰好从延迟槽之后的第一条指令继续执行，保证程序流中每条指令仅执行一次。

### 3、我们要求大家所有转发数据都来源于流水寄存器而不能是功能部件（如 DM 、 ALU ），请思考为什么？

1. **避免关键路径过长**：流水线通过寄存器切分组合逻辑来提高时钟主频。若直接从 ALU、DM 输出转发，会将相邻两级的组合逻辑串联在一个周期内（如上一级 ALU 延迟 + 转发 MUX + 本级 ALU 延迟），极大增加单周期的最大传播延迟，拉低工作频率。
2. **保证信号稳定，消除毛刺**：功能部件在周期内计算时输出端存在毛刺，直接转发会导致毛刺沿转发网络扩散，容易引发建立时间违例甚至亚稳态；流水寄存器在时钟沿锁存，能向后级提供整个周期内稳定纯净的数据。

### 4、我们为什么要使用 GPR 内部转发？该如何实现？

- **原因**：五级流水线中，W 级在时钟上升沿写寄存器，D 级在周期内组合逻辑读寄存器。当 W 级写入和 D 级读取为同一个非零寄存器时，由于时钟沿未到，D 级会读到未更新的旧值。在 GRF 内部实现转发（写穿透），让 GRF 对外表现为“同一周期先写后读”，无需顶层再额外搭建 `W -> D` 转发通路。
- **实现方式**：在读端口增加旁路选择逻辑，并保证 `$0` 恒零优先：
```verilog
assign RD1 = (A1 == 5'd0) ? 32'd0 :
             (WE && !reset && (A1 == A3)) ? WD : GRF[A1];

assign RD2 = (A2 == 5'd0) ? 32'd0 :
             (WE && !reset && (A2 == A3)) ? WD : GRF[A2];
```

### 5、我们转发时数据的需求者和供给者可能来源于哪些位置？共有哪些转发数据通路？

- **供给者**（均来自流水寄存器）：
  - `E 级`：`E_EarlyData`（`lui`、`jal` 等提前算好的结果）
  - `M 级`：`M_Result`（ALU 运算结果或前级传递的结果）
  - `W 级`：`W_Result`（DM 读出数据或传递的运算结果）

- **需求者**：
  - `D 级`：NPC 分支比较器与寄存器跳转（`D_Rs`, `D_Rt`）
  - `E 级`：ALU 操作数输入端（`E_Rs`, `E_Rt`）
  - `M 级`：DM 写内存数据端（`M_Rt`）

- **主要转发通路**：
  1. `E -> D`：`E_EarlyData -> D_Rs / D_Rt`
  2. `M -> D`：`M_Result -> D_Rs / D_Rt`
  3. `W -> D`：`W_Result -> D_Rs / D_Rt`（或由 GRF 内部转发完成）
  4. `M -> E`：`M_Result -> E_Rs / E_Rt`
  5. `W -> E`：`W_Result -> E_Rs / E_Rt`
  6. `W -> M`：`W_Result -> M_Rt`（专用于 `lw` 紧跟 `sw` 的数据相关，实现 0 阻塞）

### 6、在课上测试时，我们需要你现场实现新的指令，对于这些新的指令，你可能需要在原有的数据通路上做哪些扩展或修改？提示：你可以对指令进行分类，思考每一类指令可能修改或扩展哪些位置。

1. **计算类（如 slt, xor, 移位等）**：
   - Controller：新增 `ALUOp` 译码，配置 `ALUSrc`、`ASel`（如移位量选择）和写回寄存器 `RegAddr`；
   - ALU：在 `case(ALUOp)` 中添加相应运算逻辑。
2. **分支跳转类（如 bne, blez, bgezal 等）**：
   - Controller：配置 `NPC_Sel` 与比较类型 `CmpOp`，带链接的指定写入 `$31` 并开启条件写回标记；
   - NPC：增加相应的条件判断分支；若条件不成立，在 D 级将 `RegAddr` 清零避免误产生假冒险。
3. **访存类（如 lb, lh, sb, sh 等）**：
   - Controller：配置 `MemWr`、访存宽度 `MemSize` 以及有无符号扩展 `LoadUnsigned`；
   - DM：写入时根据低位地址屏蔽非对应字节/半字，读出时按需截取并进行符号/零扩展。
4. **条件写回类（如 movz, movn）**：
   - ALU：根据条件输出 `WriteOK` 信号；
   - 流水寄存器：在 `E -> M` 时若 `WriteOK == 0`，将 `M_RegAddr` 清零，取消写回与后续转发资格。

### 7、确定你的译码方式，简要描述你的译码器架构，并思考该架构的优势以及不足。

- **译码架构**：采用 D 级单次集中的“单热识别 + 独立行为赋值”架构。
  1. 先用 `wire IsAdd = (OpCode == ...) && (Funct == ...);` 独立识别每条指令；
  2. 在 `always @(*)` 块开头统一赋安全默认值，之后用 `if-else if` 针对每条指令独立设置其 `ALUOp`、`RegAddr`、`Tuse` 等控制信号；
  3. 控制信号随流水寄存器逐级下传，各级按需使用。

- **优势**：
  - **内聚性好、可读性高**：每条指令的所有控制信号集中在一个分支内，一目了然；
  - **加指令极快且安全**：考场新增指令只需加一行识别和一段独立的 `else if` 分支，完全不改动原有指令，极难误改出错。

- **不足**：
  - 类似指令（如 add、sub）的控制信号赋值有较多重复代码；
  - 长 `if-else if` 结构相比纯或阵列译码综合出的组合逻辑级联较深，时序优化空间稍逊。

## 选做题

### 1、[选做] 在冒险的解决中，我们引入了 AT 法，如果你有其他的解决方案，请简述你的思路，并给出一段指令序列，简单说明你是如何做到尽力转发的。

- **思路**：动态就绪标志法（简化的计分板 / Data Ready Flag）。
  为流水寄存器中的目的寄存器维护一个 `Data_Ready` 标志位：
  - `lui` / `jal` 在 E 级就绪（`Ready = 1`）；
  - 普通计算指令在 M 级就绪（ALU 算完锁存后 `Ready = 1`）；
  - `lw` 在 W 级就绪（DM 读数锁存后 `Ready = 1`）。
  阻塞判断移到真正需要数据的阶段：仅当当前阶段必须使用该寄存器、且前方最近的写入者 `Ready == 0` 时才阻塞；若 `Ready == 1` 则直接转发。

- **指令序列示例**：
```mips
lw   $1, 0($0)       # M 级 Ready=0，W 级 Ready=1
add  $2, $3, $4       # E 级 Ready=0，M 级 Ready=1
sw   $1, 4($2)       # 同时依赖 $2 (E 级基址) 和 $1 (M 级存储数据)
```
- 当 `sw` 在 E 级算地址时，`add` 刚进 M 级（`Ready = 1`），直接通过 `M -> E` 转发 `$2`，**不阻塞**；
- 当 `sw` 进入 M 级写内存时，`lw` 刚好到达 W 级（`Ready = 1`），直接通过 `W -> M` 转发 `$1`，同样**不阻塞**。
整段指令实现 0 阻塞流畅执行。

### 2、[选做] 请详细描述你的测试方案及测试数据构造策略。

- **测试方案**：
  采用“单元模块验证 $\to$ 冒险组合矩阵穷举 $\to$ 随机测试与 Golden Model 对拍”三层结构。利用 Python 搭建独立的单指令 MIPS 模拟器，自动化比对每次 GRF/DM 写入的 `(Time, PC, Addr, Data)` 轨迹。

- **数据构造策略**：
  1. **单元边界**：覆盖 GRF 内部转发穿透、`$0` 恒零写入与读取；测试复位优先于阻塞保持；测试 DM 各对齐字节读写。
  2. **冒险穷举**：将所有生产者（ALU/Load/Early）与消费者组合，分别插入 0、1、2、3 条无关指令，逐组断言实际阻塞拍数是否符合预期。
  3. **极端边界**：构造延迟槽内分支/跳转、数据极值（0、-1、最大正数、最小负数）及连续紧密数据依赖链。

### 3、[选做] 请评估我们给出的覆盖率分析模型的合理性，如有更好的方案，可一并提出。

- **合理性**：
  通过统计指令类型、数据相关与转发通路激活情况，能直观量化测试集对流水线冲突场景的覆盖，避免测试遗漏关键冒险。

- **不足**：
  只检测了“通路是否被激活”，未检测“产生的值是否真正被下游检验”（例如转发了错误数据但随后被覆盖，或写到了 `$0`，模型仍统计为已覆盖），容易产生虚假的高覆盖率。

- **改进方案**：
  1. **可观察性覆盖**：只有当转发数据最终对系统可见状态（写寄存器/写内存）产生可观测影响时才计为有效覆盖；
  2. **突变测试（Mutation Testing）**：在 RTL 中注入微小缺陷（如改反转发条件、删去复位分支），以测试集识别并拦截变异体的杀伤率来客观评估测试完备性。
