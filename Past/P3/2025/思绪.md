# BLZ

ALU新增一个小于号出口，条件跳转可以直接复用 beq 的设计

同时这里赋值赋给了rs，需要再加一个MUX在RegAddr的计算上，需要再建立一个模块BLZ，输出对应的最高取值

00表示operand1的先导0个数更多，01表示先导0个数相等，10表示operand2的先导0个数更多

OpCode：011000

```text
ori $t0, $0，0x124
ori $t1, $0, 0x458
blz $t0, $t1, 0x224
```

# LWF

这道题目感觉十分诡异，我如果需要求出来filter它需要去DM里面进行取值，但是我都去DM取值了，那么ALU可能也需要一个新的输入？不然两个地址完全都输入不了

目前决定直接破坏可维护性，在外面加入一个新的模块，输入：memword GRF[rt] 输出：一位输出，决定写入的位置

功能计算ones的数量，判断后续的路径



1. Controller 识别 LWF 指令
2. DM需要输入地址需要接入一个 ALU 的计算结果，并且传出对应的memword 可以直接利用现有接口
3. GRF 外面需要加入一个传入的地址
4. ALU 直接使用一个加号，然后和左移两位就可以了

测试指令：

```asm
ori $t1, 156
ori $t2, 196
lwf $t1, $t2, 0xff9c
结果会存入 (rt + 1)mod32
```

<mark>写给后来者</mark>：这里的LWF我是一遍A过去的，但是前面两个反而没有A过去，主要就在于他们都是用5位这个神秘的东西，我觉得logisim这点真很神秘，比如右移最多右移31位，比如数最高位1的时候最低位和没有1的时候输出完全一样，这就导致了几个情况被判定到一起了；一定一定要注意这里，谨防溢出。有的时候行为不对，可能只是边界行为，多关注**边界情况**.比如第一问偏移量为0，这里由于减法必须要多加一个一，因为会少数一个数，从而导致了最后生成的mask是31位为0，而剩下的全都是1.比如第二问数前导0，一个是0，另外一个是1，他们的前导0数目竟然完全相同amazing！！！
