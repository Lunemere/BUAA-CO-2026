# Essence Of FSM

状态不是说有一个就叫做状态，它表示的是 <mark> 我处于什么阶段，能够接收什么字符</mark>

比如这里的 `sequence_match` 我起初选定的状态是：START_BRACKET, SPACE_BEFORE_KEY, FIRST_KEY, KEY, SPACE_AFTER_KEY, COLON, SPACE_BEFORE_VALUE, VALUE, SPACE_AFTER_VALUE, COMMA, END_BRACKET, and OTHER.

意思比较明了，但是是按照我读入了什么字符去进行计算的，可以简化的是：

`START_BRACKET` ，`SPACE_BEFORE_KEY` ，`COMMA` 能接受的值一个是空格，一个是字母，他们的状态其实是一样的

| 我的状态                               | 合并后     |
| -------------------------------------- | ---------- |
| START_BRACKET、SPACE_BEFORE_KEY、COMMA | **PRE**    |
| FIRST_KEY、KEY                         | **KEY**    |
| SPACE_AFTER_KEY                        | **KEY_SP** |
| COLON、SPACE_BEFORE_VALUE              | **COLON**  |
| VALUE                                  | **VAL**    |
| SPACE_AFTER_VALUE                      | **VAL_SP** |
| END_BRACKET（以及集合外）              | **IDLE**   |
| OTHER（如果表示出错）                  | **ERR**    |

## Organization Of FSM

1. next_state 
   根据输入以及当前状态确定下一个状态，这是纯组合逻辑
2. 状态寄存器与输出寄存器
   这里是时序逻辑，一个是状态的更替，另外也更新输出需要的值

***输入和当前状态必定能够完全决定下一个状态***

如果是不能完全决定说明还有信息没有放入状态
