# 单周期 MIPS CPU 异常与中断扩展设计文档

新增测试指令：syscall mfc0 mtc0 eret nop   

`mfc0`、`mtc0`、`eret` 均属于 CP0 指令（OpCode 为 010000），其中 `mfc0` 和 `mtc0` 需要根据 `rs` 字段进一步遴选，而不是看 Funct   

新增指令编码：

| **指令** | **OpCode** | **rs** | **Funct** |
| -------- | ---------- | ------ | --------- |
| syscall  | 000000     | —      | 001100    |
| mfc0     | 010000     | 00000  | —         |
| mtc0     | 010000     | 00100  | —         |
| eret     | 010000     | 10000  | 011000    |
| nop      | 000000     | 00000  | 000000    |

# Controller

根据对应的 OpCode、Funct 以及 rs 字段进行指令匹配，动笔前需先确认好新增的控制信号端口   

输入接口：OpCode 26~31 bit   

Funct   0~5 bit   

rs      21~25 bit（专门用于区分 mfc0 和 mtc0）   

新增输出：CP0Wr     CP0 协处理器的写使能信号   

EXLClr      错误状态（EXL）清空信号，eret 指令时有效   

CP02Reg     写回 GRF 的数据是否选择来自 CP0 协处理器   

RI          未定义/非法指令异常指示信号   

Syscall     系统调用指令异常指示信号   

# ALU

新增算术溢出与访存地址计算溢出的判断逻辑   

新增输出：Overflow:    算术运算是否发生溢出   

AdELALU：   读取 DM 数据（lw）时，地址计算是否发生溢出   

AdESALU：   写入 DM 数据（sw）时，地址计算是否发生溢出   

内部实现：将参与计算的 operand 符号扩展至 33 位，利用计算结果的第 33 位和第 32 位（最高两位）是否相等来判断是否溢出（不相等则溢出）   

> 注意这些异常输出信号必须与具体指令类型绑定，仅在对应的指令下才允许输出有效值（例如只有 lw 才能触发 AdELALU，只有 sw 才能触发 AdESALU）   

# NPC

在原有跳转逻辑的基础上，增加异常/中断入口跳转和异常返回跳转   

新增输入：EPC    异常/中断处理完成后需要返回的地址（来自 CP0）   

eret     指令是否为 eret，用于异常后返回   

Req      表示当前遇到了中断或异常（原 EPC1 选择信号）   

输出：NPC    下一条指令的地址   

内部增加了两条 NPC 选择通路：当 Req 有效时，遇到了中断或异常，NPC 默认直接跳入异常处理入口 `32'h0000_4180`；当 eret 有效时，从异常状态返回，NPC 直接取 EPC 的值   

# IM

在取指阶段增加对 PC 地址合规性的检查   

新增输出：AdELIM     取指的 PC 地址是否发生异常   

地址合规判断有 3 个条件：地址必须按 4 字节对齐（即低两位为 00）；地址不能超过 `0x0000_6ffc`；地址不能小于 `0x0000_3000`   

若读取到错误的 PC 地址（即 AdELIM 为 1），输出的机器码直接填充为 `nop`（全 0），防止错误指令流入后续数据通路产生意外副作用   

# CP0

> 船新的模块！

协处理器模块，用于维护异常/中断状态并保存返回地址   

| 信号名      | 方向   | 位宽 | 描述                          |
| ----------- | ------ | ---: | ----------------------------- |
| `clk`       | input  |    1 | 时钟信号                      |
| `reset`     | input  |    1 | 复位信号                      |
| `en`        | input  |    1 | 写使能信号                    |
| `CP0Addr`   | input  |    5 | CP0 写地址                    |
| `CP0In`     | input  |   32 | CP0 写数据                    |
| `VPC`       | input  |   32 | 异常发生时的 PC               |
| `ExcCodeIn` | input  |    5 | 异常类型/异常码               |
| `EXLClr`    | input  |    1 | 清除 EXL 标志（错误状态标记） |
| `Req`       | input  |    1 | 异常发生指示信号              |
| `EPCOut`    | output |   32 | EPC 寄存器的值                |
| `CP0Out`    | output |   32 | 从 CP0/EPC 读出的值           |

需要写入时，在时钟上升沿根据 CP0Addr 和写使能 en 决定写不写、写哪个寄存器；根据 EXLClr 决定是否清空 SR 寄存器中的错误状态位（EXL）   

根据输入的异常码 ExcCodeIn 和当前错误状态决定是否响应异常；当目前已经处于错误状态（EXL 为 1）时，处理器不应再响应下一个异常   

> SR、CAUSE 寄存器在通过 mtc0 写入时，不能直接整个 32 位覆盖写入，必须严格按照允许修改的位进行按位写入，否则测试点会卡死   

# ExcUnit

单独抽离出来的异常仲裁模块，用来给各个模块解耦，汇总所有异常信号并生成最终的异常码   

| 信号名      | 方向   | 位宽 | 描述                                |
| ----------- | ------ | ---: | ----------------------------------- |
| `AdELIM`    | input  |    1 | IM访问地址异常指示（）              |
| `AdELDM`    | input  |    1 | DM访问地址异常指示（lw）            |
| `AdESDM`    | input  |    1 | DM写地址异常指示（sw）              |
| `AdELALU`   | input  |    1 | ALU 地址计算异常指示（lw）          |
| `AdESALU`   | input  |    1 | ALU 存储地址计算异常指示（sw）      |
| `Overflow`  | input  |    1 | 算术溢出异常指示                    |
| `Syscall`   | input  |    1 | 系统调用异常指示                    |
| `RI`        | input  |    1 | 非法指令异常指示                    |
| `type`      | input  |    6 | 指令类型信号                        |
| `Req`       | output |    1 | 异常请求输出，表示当前存在异常      |
| `ExcCodeIn` | output |    5 | 异常码输出，送入 CP0 的 `ExcCodeIn` |

内部按照题目给出的异常码映射表及各模块送来的异常指示，综合判断当前是否发生异常（Req）并输出对应的 ExcCodeIn   

同一条指令在流经数据通路时可能同时触发多个异常，必须严格按照指导书规定的优先级顺序进行仲裁：先判断取指异常（AdELIM），再判断未定义指令（RI）或系统调用（Syscall），最后判断 ALU 溢出及访存地址异常   

# DM

增加对访存地址合规性的检查   

新增输出：AdELDM：   lw 读取的地址是否出现异常   

AdESDM：   sw 写入的地址是否出现异常   

内部判断逻辑：lw 和 sw 访问的地址都必须按照四字节对齐，也就是 Addr 的低两位必须为 00；同时访问的地址不能越界，最大为 `32'h0000_2fff`，超出范围或未对齐均触发对应的地址异常
