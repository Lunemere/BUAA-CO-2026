# 第一题

**状态存储**：PC、GRF、DM。这三者在时钟沿更新，保存了 CPU 当前的全部状态。PC 记录执行到哪条指令，GRF 和 DM 记录数据。

**状态转移**：IM、Controller、NPC、EXT、ALU，以及各个 MUX。它们都是组合逻辑，根据当前状态计算出下一状态。

IM 虽然是存储器，但运行时内容不变，作用相当于一张"地址 → 指令"的查找表，所以归入状态转移，而不是状态存储。

这五个模块是一起作用的，不是各自孤立地完成状态转移。它们合起来构成 FSM 的次态函数：次态 = f(当前 PC, GRF, DM)。每个时钟沿到来时，PC、GRF、DM 同时更新为这个函数的输出，完成一次状态转移。

# 第二题

基本合理。

**IM 用 ROM**：程序在运行时不应被修改，用 ROM 可以防止误写。

**DM 用 RAM**：DM 需要随机读和写，用 RAM 合理。

**GRF 用 Register**：

- 名字上就是寄存器，用寄存器实现也是在模拟真实 32 位处理器的寄存器部分。
- 一个周期内需要两个读口和一个写口同时工作，Logisim 的 RAM 只有一个地址端口，做不到。
- 读必须是组合逻辑，读出的值要在同一周期内送进 ALU。用寄存器加 MUX 实现，读出不受时钟限制。

**分析与改进**：

- IM 和 DM 分开（哈佛结构）是单周期 CPU 的必要条件。一个周期内既要取指，又要读写数据，同一块存储器无法同时完成两件事。
- ROM 的不足：真实系统中程序需要由加载器写入内存，ROM 做不到；在 Logisim 中每换一个测试程序也要手动重新载入。若想支持程序加载，可以把 IM 也改用 RAM，运行时把写使能接 0。
- IM 和 DM 的地址位宽只取实际需要的 12 位，不必用满 24 位，可以节省仿真资源。

# 第三题

多实现了一个 NPC 模块，用来计算下一条指令的地址。

- **输入**：PC、imm16、NPC_Sel、zero。
- **工作方式**：分成两种情况。
  - 正常情况下输出 PC + 4。
  - beq 时输出 PC + 4 + (sign_ext(imm16) << 2)。
- **选择条件**：NPC_Sel & zero 为 1 时取跳转地址。zero 表示条件分支的条件是否成立；imm16 是以字为单位的相对跳转距离，所以要左移两位。

**设计思路**：把"下一条地址怎么算"从 PC 中单独拿出来，让 PC 只负责存储，NPC 只负责计算，状态存储和状态转移的职责分开。后续添加 j、jal、jr 等跳转指令时，只需扩展 NPC_Sel 的取值和 NPC 内部的 MUX，PC 和其他模块都不用改。

# 第四题

nop 的机器码是 0x00000000，OpCode 和 Funct 都是 000000，不匹配真值表中的任何一条指令。因此 Controller 的与阵列中没有信号为 1，所有控制信号都输出 0：

- RegWrite = 0，不写寄存器；
- MemWrite = 0，不写内存；
- NPC_Sel = 0，PC 正常 +4。

这正好就是 nop 需要的行为。所以 nop 可以和其他未定义的指令归为一类：不执行任何操作，PC 照常前进。nop 需要的控制信号取值，恰好是所有控制信号的安全默认值（全 0），不需要单独加入真值表。

另外，即使按 MIPS 标准把它当作 sll $0, $0, 0 来执行，结果也只是写 $0，而 $0 恒为 0，同样没有任何效果。

# 第五题

我手上没有 6.1 节的原测试样例，下面是在你的结论基础上补充的分析框架，具体的例子请对照原程序核实。

**结论**：有一定强度，但不高。每条指令都有覆盖，但每条指令的各种行为、尤其是边界情况几乎没有覆盖。

**具体不足**（逐条对照样例检查）：

- **ori**：没有读出高位为 1 的立即数结果（例如 0xffff），无法验证是零扩展而不是符号扩展。
- **sub**：没有验证非零数相减，也没有测结果为负数的情况。
- **add**：没有测负数或结果跨越正负号的情况。
- **lui**：没有测 lui 之后再 ori 拼出完整 32 位常数，也没有测立即数最高位为 1 的情况。
- **lw / sw**：没有测负偏移（如 -4($t0)），无法验证偏移是符号扩展；也没有测对同一地址先写后读、覆盖写。
- **beq**：应同时测跳转成立和不成立两种情况，以及向前跳和向后跳（负偏移，例如循环）。只测一种无法验证 zero 判断和符号扩展左移。
- **$0 寄存器**：没有测向 $0 写入后读出仍为 0。
- **nop**：没有验证 nop 前后寄存器和内存都不变。

**改进思路**：每条指令至少覆盖"典型值 + 边界值（0、全 1、最高位为 1）+ 正负号"，跳转覆盖"成立 / 不成立 × 向前 / 向后"。最后把所有结果写入寄存器或内存并读出比对，避免出现"算了但没检查"的情况。
